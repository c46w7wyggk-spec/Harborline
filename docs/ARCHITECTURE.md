# Harborline — Plan & Architecture

Working title **Harborline**: an original, stylized crime-and-driving sandbox set in one compact
harbor district. Not based on any existing game; all names, places and characters are invented.

## Phase 0 findings (2026-11-13)

## MVP scope (private beta)

In: one district (hub plaza, depot, harbor race loop, "Old Mint" vault, Noodle Stand business,
dealership), on-foot + arcade driving, three jobs (Courier Run, Harbor Sprint, Vault Job), cash +
Rep, 5 vehicles, one 5-level business, onboarding, persistence, rate-limited validated remotes.

Out (deferred): trading/transfers, monetization, police AI, weapons, multiple districts, UGC,
voice mechanics, leaderboards beyond the in-server board.

## Folder ownership and Rojo mapping

```
src/shared  -> ReplicatedStorage.Shared   (pure modules: config, types, math, validation)
src/server  -> ServerScriptService.Server (authoritative services; never replicated)
src/client  -> StarterPlayer.StarterPlayerScripts.Client (presentation + input only)
tests/      -> Lune unit tests for pure modules (not part of the place)
```

| Folder | Owns | Must not |
|---|---|---|
| `shared/Config/*` | All tunable numbers: jobs, vehicles, business, levels, world layout | Contain logic with side effects |
| `shared/*.luau` | Pure helpers: `Economy` math, `Validate`, `RateLimiter`, `Schema` (data defaults + migration), `JobMachine` | Touch DataStores, Players, Workspace |
| `server/Services/*` | Data, economy, vehicles, business, remotes, tutorial, world build | Trust any client value without `Validate` |
| `server/Jobs/*` | One module per job, each a state machine driven by `JobService` | Pay out directly (they return a result; `JobService` pays) |
| `client/Controllers/*` | HUD, menus, waypoints, vehicle driving, input | Decide rewards, prices or ownership |

## Data contracts

**Player profile (schema v1)** — `shared/Schema.luau`
```
{ schema=1, cash=int, rep=int, ownedVehicles={[id]=true}, business={level=int, stash=int, lastTick=int},
  cooldowns={[jobId]=unixTime}, freshness={[jobId]=number}, tutorialStep=int, stats={jobsDone=int,...},
  createdAt=int, lastSave=int }
```
Every load passes through `Schema.migrate` + `Schema.sanitize` (clamps types/ranges, drops unknown ids).

**Remotes** (folder `ReplicatedStorage.Remotes`, created by server):
- `Request: RemoteFunction(action: string, arg: any?) -> (ok: boolean, msgOrData: any)`
  Whitelisted actions only: `StartJob(jobId)`, `CancelJob()`, `SpawnVehicle(vehicleId)`,
  `BuyVehicle(vehicleId)`, `UpgradeBusiness()`, `CollectBusiness()`, `SkipTutorial()`, `GetState()`.
  Every action: per-player token bucket, type check, known-id check, distance/state check.
- `State: RemoteEvent` server→client snapshot `{cash, rep, level, owned, business, job, tutorial, nextGoal}`.
- `Notify: RemoteEvent` server→client toast `{text, kind}`.
- `OpenMenu: RemoteEvent` server→client `menuId` (fired from ProximityPrompt.Triggered on server).

The client never reports progress. Checkpoints, pickups and drop-offs are detected by the server
polling the player's HumanoidRootPart (or vehicle) position at 10 Hz against `WorldLayout` points.

## Key decisions (reversible)
1. **Map generated in code** (`WorldBuilder`) from `Config/WorldLayout` so positions shared by jobs and
   visuals cannot drift, and no binary place file is needed. Swappable for a hand-built map later
   by tagging parts with the same names.
2. **Arcade car**: one chassis part + `VehicleSeat`; driver's client owns physics and drives it with
   `LinearVelocity` (XZ plane) + `AngularVelocity` (yaw). Default Roblox controls already map
   keyboard, gamepad and touch thumbstick into `VehicleSeat.ThrottleFloat/SteerFloat`, which gives
   all three input types with one code path. Server enforces max speed per vehicle for job timing floors.
3. **Session-locked DataStore** via `UpdateAsync` with a lock `{jobId, time}`; stale lock after 120 s.
   Studio uses a separate store name (`_STUDIO` suffix); if DataStores are unavailable, Studio runs
   in memory with saving disabled; live servers kick after retries instead of loading defaults.
4. **Rewards** computed only on the server by `shared/Economy` from config + server-measured time,
   capped, and multiplied by per-job freshness (anti-grind) — numbers in `Config/Jobs.luau`.

## Risks
- Untested in real Studio by the agent: physics feel, UI layout on device, DataStore behavior.
  Mitigation: pure logic is unit-tested; Studio test script in `docs/BETA_HANDOFF.md`.
- Client-owned vehicles can be teleported by exploiters. Mitigation: server-side speed/time floors per
  job segment; rewards rejected when movement between samples exceeds vehicle max × tolerance.
- Content label: crime theme ("heist") likely raises the maturity label; see `docs/COMPLIANCE.md`.
